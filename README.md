# 长篇小说工作台 · DeepSeek Harness 插件

把"长篇不崩"这件事做成可执行的工序：一套固定的项目目录、四个工具、一个按需加载的技能。

不是"一键生成小说"。工具只做确定性的事——建骨架、读进度、查连续性、拼上下文卡；写什么、怎么写，仍然由作者决定。

## 四个工具

| 工具 | 作用 |
|---|---|
| `novel_init` | 生成固定项目树：立项、设定、人物卡、全书结构、卷纲、章纲、总表、伏笔账本、审校清单。目录非空会拒绝。 |
| `novel_status` | 进度：已写章数与字数、最近一章、下一章、章纲是否就绪、未收/超期伏笔、下一步动作。只读。 |
| `novel_check` | 连续性审计：章号缺口、正文缺细纲、总表不同步、钩子没回应、伏笔超期或无计划、字数偏差、人物失活。只读。 |
| `novel_brief` | 生成某一章的定长上下文卡：章纲四节点、前情两章、在场人物当前状态、两章内到期伏笔、世界禁忌、文风约束。只读。 |

外加技能 `novel-workflow`：顶层只放五条铁律、章级循环（带完成判据）和章纲四节点；十阶段、连续性、修订三轮放进 `skill/reference/`，按需读取。

## 安装

作为 bundle 安装（Plugins → Add plugin，或在 DSH 里用 `plugin_manager` 的 `install_bundle` 指向本目录）。补丁插入一行 `tool-novel`。

## 项目结构

```
我的小说/
├─ 00-立项.md              一句话故事、核心冲突三问、三灾难、结局画面
├─ 01-设定/
│  ├─ 世界.md              规则、边界（不能做什么）、势力、地理、禁忌
│  ├─ 文风.md              视角、句式、用词、对话、样本
│  ├─ 术语表.md            专名只定义一次
│  ├─ 时间线.md            故事时间；另列"读者已知 vs 作者真相"
│  └─ 人物/                一人一卡：动机、目标、缺陷、秘密、弧光、口吻、最近出场
├─ 02-结构/
│  ├─ 全书结构.md          三幕里程碑、五个不可逆转折、中点反转、结局
│  ├─ 卷纲.md              每卷 mini-goal、卷末高潮、下卷钩子
│  ├─ 章纲.md              滚动维护：未来 3–5 章，每章四节点
│  └─ 结构变更日志.md      改结构必须登记
├─ 03-正文/                第001章.md、第002章.md ……
├─ 04-追踪/
│  ├─ 总表.md              章节台账（单一真源）
│  └─ 伏笔账本.md          编号、层级、埋设章、计划/实际回收章、状态
└─ 05-审校/审校清单.md     结构 → 人物 → 语言，三轮
```

## 文件格式

工具靠固定的表头读取，列可以多、顺序可以换，但表头名要保留。

章纲：

```
| 章 | POV | 目标 | 转折 | 钩子 | 回应对接 | 伏笔 | 目标字数 |
```

总表：

```
| 章 | 标题 | 字数 | 状态 | 一句话摘要 | 出场人物 |
```

伏笔账本：

```
| 编号 | 描述 | 层级 | 埋设章 | 计划回收章 | 实际回收章 | 关联人物 | 状态 |
```

人物卡按字段名读取，每行一个：

```
- 姓名：林岸
- 动机：证明父亲不是自杀
- 目标：拿到 1998 年的借条
- 缺陷：不信任任何人
- 口吻：短句，回避"为什么"
- 最近出场：第 12 章
```

正文文件名必须是 `第001章.md` 这种三位补零的形式——`novel_status` 与 `novel_check` 靠它统计章号与字数。字数为非空白字符数。

## 典型会话

```
> 用 novel_init 建一个悬疑长篇，书名《长夜》，5 卷，单章 3000 字
> novel_status
> 帮我把第 1 章章纲写出来
> novel_brief chapter=1
> （写正文到 03-正文/第001章.md）
> 更新总表和伏笔账本
> novel_check
```

`novel_check` 的 error 表示硬伤（例如已写正文却没有章纲），warn 表示该处理（超期伏笔、钩子未回应），info 表示提示（字数偏差、人物久未出场）。

## 设计依据

- David 的"三层结构 + 状态系统 + 章级循环"调研见工作区 `长篇小说工作流调研.md`。
- [雪花写作法](https://www.advancedfictionwriting.com/articles/snowflake-method/)：自顶向下逐级细化，设计文档是活的。
- [Story Grid](https://storygrid.com/) 与[幕/序列/场景的转折](https://writermorph.com/zh-hant/articles/story-structure-turning-points/)：场景必须有目标—冲突—转折。
- [webnovel-author](https://github.com/sunfleeting-debug/webnovel-author)：单一真源、细纲门禁、定长上下文、双时间线、批评者不改稿。
- [create-ai-novel-workspace](https://www.npmjs.com/package/create-ai-novel-workspace)：分层摘要、章节验收、防吃书。
- 中文网文的分卷与章纲节点、伏笔分层、三轮修订，来自[塔塔写作](https://tataxiezuo.com/novel-outline-design/)的公开方法论。
- 技能的组织方式参照 [mattpocock/skills](https://github.com/mattpocock/skills) 的 `writing-for-agents`：渐进披露、每步完成判据、删掉模型已知的 no-op、用 leading words 触发。

## 边界

- 工具不调用模型、不生成情节，也不判断"这段写得好不好"。
- `novel_init` 会写文件，使用你的账号权限，不经沙箱；只在你指定的目录里创建，目录非空时拒绝。
- 其余三个工具只读；`novel_brief` 只返回文本，不写文件。
- 停用本 bundle 会移除工具与技能，已生成的项目文件不受影响。

## 开发

```bash
node test/test.mjs
```
