# 长篇小说工作流

用于规划、连载、修订长篇（几十章到几百章）。核心不是"写得好"，而是**不崩**：不丢状态、不烂伏笔、不塌中段。

## 五条铁律

1. **单一真源**：章节状态以 `04-追踪/总表.md` 为准，伏笔以 `04-追踪/伏笔账本.md` 为准。正文、摘要、统计都是派生，改了真源再谈别的。
2. **没有细纲不写正文**：章纲四节点（目标、转折、钩子、回应对接）缺一，就先补纲。
3. **定长上下文**：写每一章前只用 `novel_brief` 生成的上下文卡，不要把所有前文塞进对话。卡片长度默认 3500 字符。
4. **作者真相 ≠ 读者已知**：角色不能说出他还不该知道的事；时间线里两条线分开记。
5. **审校只诊断，不改稿**：批评意见写进审校清单，正文由写作者改；不要让"检查"顺手重写段落。

## 十阶段

| 阶段 | 产物 | 门禁 |
|---|---|---|
| 0 立项 | 一句话故事、核心冲突三问、三灾难、结局画面 | 一句话能让人追问"然后呢" |
| 1 设定 | 世界规则（含"不能做什么"）、人物卡、术语表、时间线 | 主角/对手各有动机、目标、缺陷、弧光 |
| 2 全书结构 | 三幕里程碑 + 五个不可逆转折 + 中点反转 | 每个转折都回不去 |
| 3 卷纲 | 5–10 卷：mini-goal、卷末高潮、下卷钩子 | 卷与卷有因果，不是并列 |
| 4 章纲（滚动） | 未来 3–5 章具体，每章四节点 | 每章有转折、有钩子、回应上一章 |
| 5 上下文卡 | `novel_brief` 输出 | ≤ 限长，含在场人物与待收伏笔 |
| 6 写正文 | `03-正文/第NNN章.md` | 场景有目标—冲突—转折；达成本章字数预算 |
| 7 落追踪 | 总表 + 伏笔账本 + 人物"最近出场" | 新增事实全部入账 |
| 8 审校 | `novel_check` + 三轮清单 | error 清零，warn 有处置 |
| 9 卷末审计 | 结构审计 + 修订轮次 | 修订预算未超（全书 3–5 轮） |

## 工具

```
novel_init title="长夜" genre="悬疑" volumes=5 chapterWords=3000
novel_status
novel_brief chapter=12
novel_check limit=40
```

- `novel_init`：建项目树。目录非空会拒绝；`dir` 省略时用书名建子目录。
- `novel_status`：进度、下一章、下一步动作。开工先看它。
- `novel_check`：章号缺口、正文缺细纲、总表不同步、钩子没回应、伏笔超期/无计划、字数偏差、人物失活。按 error → warn → info 排序。
- `novel_brief chapter=N`：本章的定长上下文卡（章纲、前情两章、在场人物当前状态、两章内到期伏笔、世界禁忌、文风约束）。

## 章级循环

1. `novel_status` 看下一步。
2. 补第 N 章章纲一行（四节点 + POV + 伏笔 + 目标字数）。
3. `novel_brief chapter=N`，把卡片当本章全部上下文。
4. 写 `03-正文/第NNN章.md`；场景级自检：谁想要什么、什么挡住他、结束时情况变了吗。
5. 更新总表一行（标题、状态、一句话摘要、出场人物）、相关伏笔状态、人物卡"最近出场"。
6. `novel_check`；error 清零再进下一章。

## 章纲四节点

- **目标**：本章推进的事件或揭示的信息（一句话）。
- **转折**：至少一个让情况变化、且回不去的瞬间。没有转折的场景删掉。
- **钩子**：章末"下一步会怎样"。别每章都用同一种危机。
- **回应对接**：下一章开头必须先接住上一章的钩子。写章纲时**先填回应对接，再填钩子**。

反例：`目标=主角进城；转折=无；钩子=突然出现黑衣人`——这是事件，不是章节。

## 伏笔三层

- **表**（对话/道具/场景细节）：3–5 章内回收，维持信任。
- **中**（人物过往、隐藏关系）：至少一次"几乎揭开又盖住"，再正式收。
- **深**（主题、结构对称、首尾呼应）：结局前 1–2 个卷级高潮集中收。

规则：埋设后 5 分钟内登记；每条都必须有"计划回收章"；改纲时把失效条目标"失效"并写原因，否则检查全是假阳性。

## 修订三轮（不要混着改）

1. **结构**（初稿后隔 48 小时）：每章"推进了什么"一句话测试，连续三章雷同=注水；伏笔埋收核对；产出"删章/并章/补章清单"。这一轮不碰字句。
2. **人物**：动机一致性、语言风格漂移、弧线是否有过程；抽读开场/最大危机/最终选择三场戏。
3. **语言**：最后才改字句。朗读，气息不顺处即改；先改高频场景（开场、高潮、结局）。

修订预算 3–5 轮；超过就强制收工。试读问题要具体："哪章你想跳过？""谁的行为让你出戏？"

## 常见崩法 → 对策

| 现象 | 真因 | 对策 |
|---|---|---|
| 第 60 章人物 OOC | 人物卡没随剧情更新 | 每次落追踪时同步"最近出场"与状态 |
| 伏笔烂尾 | 只记不写回收计划 | 账本必须有计划章；每 3–5 章跑一次 `novel_check` |
| 中段塌陷 | 只有章纲没有卷级 mini-goal | 每卷末做结构审计；补中点反转 |
| 越写越忘 | 上下文无限膨胀 | 只用 `novel_brief`；事实沉淀到设定与总表 |
| 角色提前泄底 | 作者真相与读者已知混了 | 时间线里单列"谁在何时知道" |
| 全书像 AI 写的 | 直接生成整章、语体趋同 | 用样本锚定文风；AI 只出报告与备选，不整段替换 |

## 文件约定

- 正文文件名固定 `第001章.md`（三位补零），工具靠它统计章号与字数。
- 总表列：章 / 标题 / 字数 / 状态 / 一句话摘要 / 出场人物。
- 章纲列：章 / POV / 目标 / 转折 / 钩子 / 回应对接 / 伏笔 / 目标字数。
- 伏笔列：编号 / 描述 / 层级 / 埋设章 / 计划回收章 / 实际回收章 / 关联人物 / 状态。
- 人物卡字段用 `- 动机：` `- 目标：` `- 缺陷：` `- 口吻：` `- 最近出场：`，工具按字段名读取。
- 改结构必须写 `02-结构/结构变更日志.md`，并回查伏笔、时间线、人物三项。
