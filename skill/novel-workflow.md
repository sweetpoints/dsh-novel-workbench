# 长篇小说工作流

把长篇写到"不崩"：状态外置、章级门禁、定长上下文。工具是 `novel_*`，项目是一套固定的 Markdown 文件。

用于规划或续写长篇、连载、系列：补章纲、生成上下文卡、查连续性、做修订。
不用于短篇（<5 章）或非虚构——直接写更快。

## 五条铁律

1. **单一真源**：章节状态只认 `04-追踪/总表.md`，伏笔只认 `04-追踪/伏笔账本.md`。改了真源，派生文件才有意义。
2. **没有细纲不写正文**：章纲四节点缺一，先补纲。工具会把"已写正文但没有章纲"报成 error。
3. **定长上下文**：写每一章前只加载 `novel_brief` 的卡片，不把前文整段塞进对话。
4. **作者真相 ≠ 读者已知**：角色不能说出他还不该知道的事。时间线里单列"谁在何时知道"。
5. **审校只诊断，不改稿**：意见写进审校清单；正文由写作者改，检查者不顺手重写。

## 章级循环

每一步都有 done 条件，不满足不进下一步。

1. `novel_status` —— done：知道下一章、error 数、超期伏笔。
2. 补第 N 章章纲一行：目标 / 转折 / 钩子 / 回应对接 + POV + 伏笔 + 目标字数 —— done：四个方法字段都非空。一章超过 3 场戏时，再写 `02-结构/细纲/第NNN章.md`。
3. `novel_brief chapter=N` —— done：卡片含上游约束（全书/本卷）、本章细纲（有详版带详版）、前情、人物、待收伏笔、禁忌。
4. 写 `03-正文/第NNN章.md` —— done：每场戏有目标—冲突—转折；字数在目标 ±50% 内。
5. 落追踪：总表一行、伏笔状态、相关人物"最近出场"、影响后续的决定 —— done：四处都更新，决定写进 `06-工作台/决策记录.md`。
6. `novel_check` —— done：error 为 0；warn 有明确处置（改、或登记为暂缓）。

## 章纲四节点

这是方法的核心，不是模板填空：

- **目标**：本章推进的事件或揭示的信息，一句。
- **转折**：至少一个让情况变化、且回不去的瞬间。没有转折的场景删掉。
- **钩子**：章末"下一步会怎样"。别每章都用同一种危机。
- **回应对接**：下一章开头必须先接住上一章的钩子。**先填回应对接，再填钩子。**

反例：`目标=主角进城；转折=无；钩子=突然出现黑衣人`——这是事件，不是章节。

## 失败模式词表

先命名，再修。名字对上了，修法通常在对应文件里。

状态分裂 · 细纲缺失 · 钩子断裂 · 伏笔烂尾 · 人物失活 · 中段塌陷 · 上下文膨胀 · 提前泄底 · 理由丢失

## 反模式

- 把整本前文塞进对话，而不是用 `novel_brief`。
- 一章写完不落账——下一章开始就会矛盾。
- 用润色掩盖结构问题：先结构，再人物，最后才语言。
- 只记"写了什么"不记"为什么"：三个月后你会把它当成既定事实，而不是一个可回退的选择。
